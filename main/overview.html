What is TensorDict?#

A TensorDict is a dictionary of tensors that behaves like one tensor. You index, reshape, move, and save the whole group with one call. TensorDict also makes sure that every tensor keeps the dimensions that the group shares. A TensorClass gives the same behavior to a class with typed fields and methods.

TensorDict: the dict form#

All the entries of a TensorDict share their first dimensions, called the batch size. This TensorDict holds the state of 4 robots: 7 joint angles for each robot, and the camera images in a nested TensorDict:

>>> import torch
>>> from tensordict import TensorDict
>>> robots = TensorDict(
...     {
...         "joints": torch.zeros(4, 7),
...         "camera": {
...             "rgb": torch.zeros(4, 3, 32, 32, dtype=torch.uint8),
...             "depth": torch.zeros(4, 32, 32),
...         },
...     },
...     batch_size=[4],
... )

A string, or a tuple of strings for a nested entry, reads one entry. Any other index applies to the batch dimensions of every entry, nested entries too. Device moves and dtype casts also apply to every entry:

>>> robots["camera", "depth"].shape
torch.Size([4, 32, 32])
>>> robots[:2]["camera", "rgb"].shape
torch.Size([2, 3, 32, 32])
>>> robots.to(torch.float64)["camera", "rgb"].dtype
torch.float64

You can also save a TensorDict to disk, send it to other processes or nodes, and pass it to torch.nn.Module objects through tensordict.nn. With torch.func, a TensorDict of parameters makes model ensembles and parameter edits shorter to write (see torch.compile, torch.func, torch.export, and CUDA graphs). TensorDict started as part of TorchRL and is now a separate library.

TensorClass: the class form#

A TensorClass declares its fields as class annotations, like a dataclass, and it has the tensor behavior of a TensorDict. A method that you write once runs on one item or on a batch of any shape. This class holds bounding boxes for object detection, with a batch of 8 images and 5 boxes for each image:

>>> from tensordict import TensorClass
>>> class Box(TensorClass):
...     low: torch.Tensor  # [*batch, 2], the lower corner
...     high: torch.Tensor  # [*batch, 2], the upper corner
...
...     def area(self) -> torch.Tensor:
...         return (self.high - self.low).prod(-1)
>>> boxes = Box(
...     low=torch.zeros(8, 5, 2), high=torch.full((8, 5, 2), 2.0), batch_size=[8, 5]
... )
>>> boxes.area().shape
torch.Size([8, 5])
>>> boxes[0, 1].area()
tensor(4.)
>>> type(boxes.reshape(40)).__name__
'Box'

Use a TensorDict when your code chooses the keys at run time. Use a TensorClass when the fields are fixed and you want methods on them. Which container should I use? covers the other containers.

What it replaces: a dictionary and tree_map#

torch.utils._pytree.tree_map() applies a function to each tensor of a nested dictionary. It does some of the work of a TensorDict, but it does not know about a batch dimension. The examples below use a batch of 3 graphs, each with 5 nodes and 10 edges:

>>> from torch.utils._pytree import tree_map
>>> graphs = {
...     "nodes": torch.randn(3, 5, 16),
...     "edges": {"index": torch.randint(5, (3, 2, 10)), "weight": torch.rand(3, 10)},
... }
>>> td = TensorDict(graphs, batch_size=[3])

To split the graphs with tree_map, you get one dictionary of tuples. You must then build the three dictionaries by hand, and that code grows with each level of nesting:

>>> unbound = tree_map(lambda x: x.unbind(0), graphs)
>>> type(unbound["edges"]["weight"])
<class 'tuple'>
>>> samples = [
...     {
...         "nodes": unbound["nodes"][i],
...         "edges": {
...             "index": unbound["edges"]["index"][i],
...             "weight": unbound["edges"]["weight"][i],
...         },
...     }
...     for i in range(3)
... ]

unbind() returns the three tensordicts directly, at any nesting depth. split() and chunk() work the same way:

>>> g0, g1, g2 = td.unbind(0)
>>> g0["edges", "weight"].shape
torch.Size([10])

tree_map applies an index to each tensor as it is, so the result depends on the shape of each tensor. A TensorDict applies the index to the batch dimensions only:

>>> mapped = tree_map(lambda x: x[..., :2], graphs)
>>> mapped["nodes"].shape, mapped["edges"]["weight"].shape
(torch.Size([3, 5, 2]), torch.Size([3, 2]))
>>> sliced = td[..., :2]
>>> sliced["nodes"].shape, sliced["edges", "weight"].shape
(torch.Size([2, 5, 16]), torch.Size([2, 10]))

A dictionary accepts a tensor of any shape. A TensorDict raises an error when an entry does not match the batch size:

>>> graphs["edges"]["type"] = torch.zeros(5)  # no error
>>> td["edges", "type"] = torch.zeros(5)
Traceback (most recent call last):
...
RuntimeError: batch dimension mismatch, got self.batch_size=torch.Size([3]) and value.shape=torch.Size([5]) for key 'type'. The leading dimensions of a value must match the batch size.

TensorDict is registered as a pytree node, so tree_map and torch.func also work on a TensorDict. The result is a TensorDict:

>>> type(tree_map(lambda x: x + 1, td)).__name__
'TensorDict'

What it is not#

A TensorDict is not exactly a dict. A dict is a good model: a TensorDict has the methods of a mapping, keys, values, items, get, pop, update, in, and **data. But for x in data, len(data), bool(data), and data == other follow the rules of a tensor:

>>> isinstance(robots, dict)
False
>>> len(robots)  # the size of the first batch dimension, not the number of keys
4
>>> sorted(robots.keys())
['camera', 'joints']

A TensorDict is not exactly a dict lists these differences.

A TensorDict is not a torch.Tensor either. Each entry keeps its own dtype, device, and the dimensions after the batch dimensions. robots.shape is the batch size, not the shape of an entry:

>>> isinstance(robots, torch.Tensor)
False
>>> robots.shape
torch.Size([4])

A TensorDict is not a data frame. For tables that you filter, group, and join, use pandas or Polars. to_pandas() and from_pandas() convert between the two.
