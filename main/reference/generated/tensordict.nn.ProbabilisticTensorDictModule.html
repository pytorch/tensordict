ProbabilisticTensorDictModule#

class tensordict.nn.ProbabilisticTensorDictModule(in_keys: NestedKey | List[NestedKey] | Dict[str, NestedKey], out_keys: NestedKey | List[NestedKey] | None = None, *, default_interaction_type: InteractionType = InteractionType.DETERMINISTIC, distribution_class: type = <class 'tensordict.nn.distributions.continuous.Delta'>, distribution_kwargs: dict | None = None, return_log_prob: bool = False, log_prob_keys: List[NestedKey] | None = None, log_prob_key: NestedKey | None = None, cache_dist: bool = False, n_empirical_estimate: int = 1000, num_samples: int | torch.Size | None = None, generator: torch.Generator | int | NestedKey | None = None)#

Bases: TensorDictModuleBase

A module that builds a distribution from entries of a tensordict and writes a value from it.

The module has no parameters. It reads the distribution parameters at in_keys, builds distribution_class(**params, **distribution_kwargs), and writes one value at each of the out_keys. To compute the parameters with a network, put a TensorDictModule before this module in a ProbabilisticTensorDictSequential. To get the distribution without a value, call get_dist(). To get the log-probability of a value, call log_prob(). See Probabilistic modules for a guide.

The value depends on the interaction type: the value of interaction_type() if it is set (see set_interaction_type), default_interaction_type otherwise. See InteractionType for what each type reads from the distribution.

The default distribution_class is Delta, which always returns its parameter. With it, the module copies its input to out_keys.

If every key in out_keys is already in the input and skip_existing() is True (see set_skip_existing), the module returns the input unchanged. Otherwise it computes a new value and overwrites the entry.

With return_log_prob=True and the RANDOM interaction type, the module draws and scores the value in one call if the distribution defines the method: dist.rsample_and_log_prob(sample_shape) if dist.has_rsample, dist.sample_and_log_prob(sample_shape) otherwise. The method returns a (sample, log_prob) tuple, with log_prob in the layout of dist.log_prob. Define it when dist.log_prob(sample) cannot recover the draw exactly, for example for a tanh-squashed normal that saturates. Otherwise the module calls dist.log_prob on the sample. The torch.distributions classes do not define these methods; CompositeDistribution defines both.

Log-probability keys

With return_log_prob=True, the module also writes the log-probability of the value. The key depends on composite_lp_aggregate() (False by default, see set_composite_lp_aggregate) and on the number of sampled keys:

Case

composite_lp_aggregate() is False (default)

composite_lp_aggregate() is True

One sampled key, "action"

"action_log_prob"

"sample_log_prob"

One nested key, ("agent", "action")

("agent", "action_log_prob")

"sample_log_prob"

Several sampled keys from a CompositeDistribution, "cont" and ("nested", "disc")

"cont_log_prob" and ("nested", "disc_log_prob")

The same two entries, and "sample_log_prob" with their sum

Several probabilistic modules in a ProbabilisticTensorDictSequential

One <key>_log_prob entry per sampled key

Each module writes "sample_log_prob", so the entry holds the log-probability of the last module only. Call ProbabilisticTensorDictSequential.log_prob() to get the sum.

The suffix _log_prob goes on the last element of a nested key. Pass log_prob_key (one sampled key) or log_prob_keys (several sampled keys) to choose other keys.

log_prob() returns a tensor, except for a CompositeDistribution while composite_lp_aggregate() is False: then it returns a TensorDict with the <key>_log_prob entries of the table. With True, the tensor is the sum over the sampled keys and their event dimensions.

Set composite_lp_aggregate() before you build the module. If the value changed since then, log_prob_key, log_prob_keys, log_prob() and a call with return_log_prob=True can raise a RuntimeError.

Parameters:

  • in_keys (NestedKey, list of NestedKey, or dict) – the entries that hold the parameters of the distribution. With a key or a list of keys, the last element of each key is the keyword argument of distribution_class that it feeds: ["loc", "scale"] for a Normal, and ("agent", "loc") feeds loc. With a dict, the keys are the keyword arguments and the values are the tensordict keys: {"loc": "mu", "scale": "sigma"}.

  • out_keys (NestedKey or list of NestedKey, optional) – the keys where the values are written, one per value that the distribution returns. If the input already has these keys, the module overwrites them, unless skip_existing() is True. Defaults to None: for a CompositeDistribution, the values of the name_map of distribution_kwargs if it has one, and the keys of its distribution_map otherwise. A component that name_map leaves out is written under its own name but is not in out_keys, and the module warns. Starting with TensorDict 0.17, the default will change to out_keys that include these components. For another distribution, None gives the key "_": the module writes the sample there, and warns the first time it does. Starting with TensorDict 0.17, the default will change to not writing the sample at "_", which marks an output that is not written, as in TensorDictModule. Pass out_keys to keep the current keys.

Keyword Arguments:

  • default_interaction_type (InteractionType or str, optional) – the interaction type that the module uses when interaction_type() returns None, that is outside of a set_interaction_type block. MODE and MEDIAN raise NotImplementedError if the distribution does not have them. MEAN averages n_empirical_estimate samples if the distribution has no mean. TorchRL collectors sample with InteractionType.RANDOM by default (their exploration_type argument). Defaults to InteractionType.DETERMINISTIC.

  • distribution_class (type or Callable, optional) – the distribution class, or a callable that takes the parameters as keyword arguments and returns a torch.distributions.Distribution. For a CompositeDistribution, distribution_kwargs holds its distribution_map, and out_keys can be left out. Defaults to Delta.

  • distribution_kwargs (dict, optional) – extra keyword arguments passed to distribution_class, for example constants. To move the tensors in it with the module (module.to(device), module.to(dtype)), pass a TensorDictParams. Defaults to None.

  • return_log_prob (bool, optional) – if True, the module also writes the log-probability of the value, at the keys of the table above. Defaults to False.

  • log_prob_keys (list of NestedKey, optional) – the keys of the log-probabilities, one per sampled key, in place of the <key>_log_prob defaults, including for a CompositeDistribution. If composite_lp_aggregate() is True, passing it raises a RuntimeError. Defaults to None.

  • log_prob_key (NestedKey, optional) –

    the key of the log-probability: of the one sampled key, or, while composite_lp_aggregate() is True, of their sum. With several sampled keys while it is False, passing it raises a RuntimeError. Defaults to None, which gives the key of the table above.

    With return_log_prob=True, a custom log_prob_key or log_prob_keys entry equal to a sample key, inside one, or holding one raises a ValueError, because the log-probability would overwrite the sample. The check runs when distribution_class is a class (and, for a CompositeDistribution, when distribution_kwargs holds its distribution_map).

  • cache_dist (bool, optional) – has no effect. Deprecated: passing True warns, and the argument will be removed in TensorDict 0.17. Defaults to False.

  • n_empirical_estimate (int, optional) – the number of samples that MEAN averages when the distribution has no mean. Defaults to 1000.

  • num_samples (int or Size, optional) – the number of values per call. The output tensordict is expanded to num_samples + batch_size, and each value gets these leading dimensions. With the RANDOM interaction type, each value is a new draw. With another interaction type, the module repeats its one deterministic value. Defaults to None: one value, no extra dimension.

  • generator (Generator, int or NestedKey, optional) –

    the random number generator of the sampling, used by the RANDOM interaction type and by the sampled estimate of MEAN.

    • None (default): the global PyTorch generator.

    • a torch.Generator: used for every call. Its state advances in place, so consecutive calls draw different values. It must be on the device of the distribution parameters.

    • an int: the seed of a CPU generator that the constructor creates, then used as above.

    • a NestedKey: the key of an entry of the input, read at each call. The entry holds a torch.Generator, used as above, or an integer seed (a scalar tensor or an int). A seed gives a new generator, and after sampling the module writes a new seed, drawn from that generator, back at the key. If the input has no such entry, the global generator is used.

    Sampling with a generator does not change the state of the global generator, and works with every distribution. Under torch.compile(), the argument is ignored, without a warning.

Examples

Sample from a normal distribution, and write the log-probability of the sample:

>>> import torch
>>> from torch import distributions as d
>>> from tensordict import TensorDict
>>> from tensordict.nn import InteractionType, ProbabilisticTensorDictModule
>>> module = ProbabilisticTensorDictModule(
...     in_keys=["loc", "scale"],
...     out_keys=["action"],
...     distribution_class=d.Normal,
...     default_interaction_type=InteractionType.RANDOM,
...     return_log_prob=True,
... )
>>> _ = torch.manual_seed(0)
>>> td = module(TensorDict(loc=torch.zeros(3), scale=torch.ones(3)))
>>> td["action"]
tensor([ 1.5410, -0.2934, -2.1788])
>>> td["action_log_prob"]
tensor([-2.1063, -0.9620, -3.2925])

Compute the parameters with a network, in a ProbabilisticTensorDictSequential:

>>> from tensordict.nn import (
...     ProbabilisticTensorDictModule,
...     ProbabilisticTensorDictSequential,
...     TensorDictModule,
... )
>>> from tensordict.nn.distributions import NormalParamExtractor
>>> from torch.distributions import Normal, Independent
>>> td = TensorDict(
...     {"input": torch.randn(3, 4), "hidden": torch.randn(3, 8)}, [3]
... )
>>> net = torch.nn.GRUCell(4, 8)
>>> module = TensorDictModule(
...     net, in_keys=["input", "hidden"], out_keys=["params"]
... )
>>> normal_params = TensorDictModule(
...     NormalParamExtractor(), in_keys=["params"], out_keys=["loc", "scale"]
... )
>>> def IndepNormal(**kwargs):
...     return Independent(Normal(**kwargs), 1)
>>> prob_module = ProbabilisticTensorDictModule(
...     in_keys=["loc", "scale"],
...     out_keys=["action"],
...     distribution_class=IndepNormal,
...     return_log_prob=True,
... )
>>> td_module = ProbabilisticTensorDictSequential(
...     module, normal_params, prob_module
... )
>>> params = TensorDict.from_module(td_module)
>>> with params.to_module(td_module):
...     _ = td_module(td)
>>> print(td)

    fields={
        action: Tensor(shape=torch.Size([3, 4]), device=cpu, dtype=torch.float32, is_shared=False),
        action_log_prob: Tensor(shape=torch.Size([3]), device=cpu, dtype=torch.float32, is_shared=False),
        hidden: Tensor(shape=torch.Size([3, 8]), device=cpu, dtype=torch.float32, is_shared=False),
        input: Tensor(shape=torch.Size([3, 4]), device=cpu, dtype=torch.float32, is_shared=False),
        loc: Tensor(shape=torch.Size([3, 4]), device=cpu, dtype=torch.float32, is_shared=False),
        params: Tensor(shape=torch.Size([3, 8]), device=cpu, dtype=torch.float32, is_shared=False),
        scale: Tensor(shape=torch.Size([3, 4]), device=cpu, dtype=torch.float32, is_shared=False)},
    batch_size=torch.Size([3]),
    device=None,
    is_shared=False)
>>> with params.to_module(td_module):
...     dist = td_module.get_dist(td)
>>> print(dist)
Independent(Normal(loc: torch.Size([3, 4]), scale: torch.Size([3, 4])), 1)
>>> # we can also apply the module to the TensorDict with vmap
>>> from torch import vmap
>>> params = params.expand(4)
>>> def func(td, params):
...     with params.to_module(td_module):
...         return td_module(td)
>>> td_vmap = vmap(func, (None, 0))(td, params)
>>> print(td_vmap)

    is_shared=False)

reset_parameters_recursive(parameters: TensorDictBase | None = None) → TensorDictBase | None#

Resets the parameters of every submodule that has a reset_parameters method.

Without parameters, the parameters of the module are reset in place. With parameters, the module is left as it is: the values in parameters are reset in place, as if they were loaded into the module (see to_module()). Use this for parameters kept outside the module, for example in a functional call. Values that share their storage with the module parameters, such as those of from_module(), reset the module too.

Parameters:

parameters (TensorDictBase, optional) – the parameters to reset, with the structure of from_module() and an empty batch size. Defaults to None, which resets the parameters of the module.

Returns:

None without parameters. Otherwise a new tensordict of tensors that share their storage with parameters and require gradients.

Raises:

RuntimeError – if parameters has batch dimensions.

Without parameters, the call warns if no submodule has a reset_parameters method.

Examples

>>> import torch
>>> from tensordict import TensorDict
>>> from tensordict.nn import TensorDictModule
>>> from torch import nn
>>> net = nn.Sequential(nn.Linear(2, 3), nn.ReLU())
>>> old_weight = net[0].weight.clone()
>>> module = TensorDictModule(net, in_keys=["x"], out_keys=["y"])
>>> module.reset_parameters_recursive()
>>> torch.equal(old_weight, net[0].weight)
False

The parameters can also live outside the module:

>>> params = TensorDict.from_module(module).clone()
>>> old_params = params.clone()
>>> _ = module.reset_parameters_recursive(params)
>>> (old_params == params).any()
False
>>> torch.equal(net[0].weight, old_params["module", "0", "weight"])
True
select_out_keys(*out_keys) → TensorDictModuleBase#

Keeps only some of the out_keys in the output of the module, and returns the module.

Use it to drop intermediate outputs, for example those of a TensorDictSequential. The module changes in place: out_keys becomes the selected keys, and out_keys_source keeps the full list. A call still computes all the outputs, and then removes the ones that are not selected. It removes nothing else, so the input entries stay in the output. When you call the module with tensors (see dispatch()), it returns only the selected outputs. reset_out_keys() undoes the selection.

Parameters:

*out_keys (NestedKey) – the keys to keep. Each one must be in out_keys.

Returns:

self.

Raises:

ValueError – if a key is not in out_keys. The error names the missing keys, and is also a RuntimeError.

Examples

>>> import torch
>>> from tensordict import TensorDict
>>> from tensordict.nn import TensorDictModule
>>> mod = TensorDictModule(
...     lambda x, y: (x + 2, y + 2), in_keys=["a", "b"], out_keys=["c", "d"]
... )
>>> _ = mod.select_out_keys("d")
>>> mod.out_keys, mod.out_keys_source
(['d'], ['c', 'd'])
>>> td = mod(TensorDict(a=torch.zeros(()), b=torch.ones(())))
>>> sorted(td.keys())
['a', 'b', 'd']
>>> mod(torch.zeros(()), torch.ones(()))
tensor(3.)
>>> _ = mod.reset_out_keys()
>>> sorted(mod(TensorDict(a=torch.zeros(()), b=torch.ones(()))).keys())
['a', 'b', 'c', 'd']

It works on a TensorDictSequential too:

>>> from tensordict.nn import TensorDictSequential
>>> seq = TensorDictSequential(
...     TensorDictModule(lambda x: x + 1, in_keys=["x"], out_keys=["y"]),
...     TensorDictModule(lambda y: y + 1, in_keys=["y"], out_keys=["z"]),
... )
>>> _ = seq.select_out_keys("z")
>>> sorted(seq(TensorDict(x=torch.zeros(()))).keys())
['x', 'z']
