Batch size, shapes, and indexing#

The batch size is the shape that all the entries of a TensorDict share at the front. With it, one index, one reshape, or one unbind applies to every tensor of the group. A tensor of the wrong shape raises an error when you add it.

Batch size and batch dimensions#

The leading dimensions that all the entries share are the batch dimensions. batch_dims is their number. The dimensions that come after them are the feature dimensions of each entry, and they can differ from entry to entry.

In this example, a tensordict holds 3 time steps of 2 robots. Each robot has 4 joint angles and one battery level:

>>> import torch
>>> from tensordict import TensorDict
>>> td = TensorDict(
...     {
...         "joints": torch.zeros(2, 3, 4),
...         "battery": torch.zeros(2, 3),
...     },
...     batch_size=[2, 3],
... )
>>> td.batch_size
torch.Size([2, 3])
>>> td.batch_dims
2
>>> td["joints"].shape[td.batch_dims:]  # the feature dimensions of "joints"
torch.Size([4])
>>> td["battery"].shape[td.batch_dims:]
torch.Size([])

td.shape and td.size() return the batch size. td.ndim and td.dim() return batch_dims. td.numel() is the number of elements in the batch (here 6), not the number of values in the tensors.

A TensorClass has a batch size too, with the same rules for its typed fields (see TensorClass).

The leading dimensions of each entry must be equal to the batch size. If they are not, the constructor and each write raise a RuntimeError that names the key:

>>> td["contact"] = torch.zeros(3)
Traceback (most recent call last):
...
RuntimeError: batch dimension mismatch, got self.batch_size=torch.Size([2, 3]) and value.shape=torch.Size([3]) for key 'contact'. The leading dimensions of a value must match the batch size.

TensorDict stores a Python number as a 0-dim tensor. If the batch size is not empty, a number therefore gives the same error. To store one number for each element, expand it to the batch size. To store one number for the whole batch, see Non-tensor data and unbatched entries.

>>> td["contact"] = torch.tensor(False).expand(td.batch_size)
>>> td["contact"].shape
torch.Size([2, 3])

A nested tensordict is an entry too. Its batch size must start with the batch size of its parent, and it can have more batch dimensions. When you give a dictionary as a value, the nested tensordict gets the batch size of the parent:

>>> td["target"] = {"joints": torch.zeros(2, 3, 4)}
>>> td["target"].batch_size
torch.Size([2, 3])

To store a tensor that does not have the batch dimensions, wrap it in an UnbatchedTensor (see UnbatchedTensor).

Empty batch size#

If you do not give a batch size, it is torch.Size([]): no batch dimensions. TensorDict does not infer it from the entries. With an empty batch size, the entries can have any shape, but you cannot index the tensordict or iterate over it:

>>> data = TensorDict({"images": torch.zeros(3, 4), "labels": torch.zeros(3)})
>>> data.batch_size
torch.Size([])
>>> data[0]
Traceback (most recent call last):
...
RuntimeError: indexing a tensordict with td.batch_dims==0 is not permitted. Got index 0.

TensorDict() creates a tensordict with no entries and an empty batch size.

Infer the batch size#

To infer the batch size from the entries, do one of these:

  • Pass auto_batch_size=True to from_dict().

  • Call auto_batch_size_() on an existing tensordict. It changes the tensordict and returns it.

Both set the batch size to the longest list of leading dimensions that all the entries share. Use batch_dims to set a maximum number of batch dimensions:

>>> TensorDict.from_dict(
...     {"images": torch.zeros(3, 4), "labels": torch.zeros(3)}, auto_batch_size=True
... ).batch_size
torch.Size([3])
>>> data = TensorDict({"images": torch.zeros(3, 4, 5), "masks": torch.zeros(3, 4)})
>>> data.auto_batch_size_().batch_size
torch.Size([3, 4])
>>> data.auto_batch_size_(batch_dims=1).batch_size
torch.Size([3])

auto_batch_size_ also gives each nested tensordict the longest batch size of its own entries.

Change the batch size#

You can assign a new batch size if all the entries are compatible with it. An empty batch size is always compatible:

>>> data = TensorDict({"images": torch.zeros(3, 4)}, batch_size=[3])
>>> data.batch_size = [3, 4]
>>> data.batch_size = [4]
Traceback (most recent call last):
...
RuntimeError: the Tensor images has shape torch.Size([3, 4]) which is incompatible with the batch-size torch.Size([4]).

A LazyStackedTensorDict (see Stacking and variable-size data) does not accept a new batch size, not even an empty one. Call to_tensordict() first.

Indexing#

An index on a TensorDict follows one rule:

  • A string, or a tuple of strings, reads one entry (see Keys, nested keys, and locking).

  • Any other index applies to the batch dimensions of all the entries at once: an integer, a slice, ..., None, a list or tensor of integers, or a boolean mask.

The result of a batch index is a TensorDict. Because the index applies to the batch dimensions, td[..., :2]["joints"] and td["joints"][..., :2] are different:

>>> td = TensorDict({"joints": torch.zeros(2, 3, 4), "battery": torch.zeros(2, 3)}, batch_size=[2, 3])
>>> td[0].batch_size  # robot 0, all time steps
torch.Size([3])
>>> td[..., :2]["joints"].shape  # the first 2 time steps
torch.Size([2, 2, 4])
>>> td["joints"][..., :2].shape  # the first 2 joints
torch.Size([2, 3, 2])
>>> td[:, None].batch_size
torch.Size([2, 1, 3])

A boolean mask selects elements of the leading batch dimensions, as for a tensor. Its shape must match those dimensions:

>>> mask = torch.tensor([[True, False, True], [False, False, True]])
>>> td[mask].batch_size
torch.Size([3])
>>> td[mask]["joints"].shape
torch.Size([3, 4])
>>> td[torch.tensor([True, False])].batch_size
torch.Size([1, 3])

A list of strings is not a key selection. To keep some keys, use select() (see Keys, nested keys, and locking).

Indexing follows the rules of torch for storage. An integer or a slice gives views, so an in-place change of an entry of the result changes the original. A mask or a tensor of indices gives copies. A new key that you write into the result does not appear in the original:

>>> sub = td[0]
>>> sub["battery"] += 1
>>> td["battery"]
tensor([[1., 1., 1.],
        [0., 0., 0.]])
>>> sub["new"] = torch.zeros(3)
>>> "new" in td
False

To write into the batch elements of the original, assign to an index. The value can be a TensorDict with the batch size of the indexed result, or a number or tensor that broadcasts to each entry:

>>> td[1] = TensorDict({"joints": torch.ones(3, 4), "battery": torch.ones(3)}, batch_size=[3])
>>> td[:, 0] = 0
>>> td["battery"]
tensor([[0., 1., 1.],
        [0., 1., 1.]])

If you write a TensorDict into an index of an empty tensordict, the first write creates the entries. See Lazy pre-allocation.

Shape operations#

The shape operations of a TensorDict apply the same operation to the batch dimensions of each entry. They do not change the feature dimensions, and their dimension arguments count batch dimensions only:

>>> td = TensorDict({"joints": torch.zeros(2, 3, 4), "battery": torch.zeros(2, 3)}, batch_size=[2, 3])
>>> td.reshape(6)["joints"].shape
torch.Size([6, 4])
>>> td.permute(1, 0)["joints"].shape
torch.Size([3, 2, 4])
>>> td.unsqueeze(-1)["joints"].shape  # a new last batch dimension, before the 4 joints
torch.Size([2, 3, 1, 4])
>>> td.flatten(0, 1).unflatten(0, (2, 3)).batch_size
torch.Size([2, 3])
>>> [t.batch_size for t in td.unbind(1)]
[torch.Size([2]), torch.Size([2]), torch.Size([2])]
>>> [t.batch_size for t in td.split([2, 1], dim=1)]
[torch.Size([2, 2]), torch.Size([2, 1])]

The other shape operations are view(), transpose(), squeeze(), expand(), chunk(), repeat(), and repeat_interleave(). As for tensors, view, permute, unbind, and expand return views of the same storage. expand repeats the same memory, so an in-place write into an expanded entry raises a RuntimeError. Call clone() first to get separate copies.

To join tensordicts with torch.stack() and torch.cat(), see Stacking and variable-size data.

Dimension names#

You can give a name to each batch dimension, as with the named tensors of PyTorch. names has one entry for each batch dimension, and None means that the dimension has no name. Give the names at construction, or set them later:

>>> td = TensorDict(batch_size=[3, 4], names=["robot", None])
>>> td.names
['robot', None]
>>> td = td.refine_names(..., "time")
>>> td.names
['robot', 'time']
>>> td.names = ["env", "step"]
>>> td = td.rename("agent", "t")
>>> td.names
['agent', 't']
>>> td = td.rename(agent="robot")
>>> td.names
['robot', 't']

The names follow the shape operations:

>>> td[0].names  # indexing removes the name of the indexed dimension
['t']
>>> td.permute(1, 0).names
['t', 'robot']
>>> td.unsqueeze(0).names  # a new dimension has no name
[None, 'robot', 't']
>>> td.reshape(12).names
[None]

If the number of names is not batch_dims, TensorDict raises a ValueError. A nested tensordict has the names of its parent for the shared batch dimensions. The shape operations take dimension numbers, not names.

A TensorDict is not exactly a dict#

A dict is a good model of a TensorDict. A TensorDict has the mapping methods of a dict: keys(), values(), items(), get(), pop(), update(), and setdefault(), and it unpacks with **td. The operations below are the exceptions. Most of them follow the rules of a tensor:

Iteration

for x in td iterates over the first batch dimension, like a tensor. Each x is a TensorDict. A tensordict with no batch dimensions raises a TypeError. To iterate over the entries, use keys(), values(), or items().

len

len(td) is the size of the first batch dimension, or 0 if the batch size is empty. len(td.keys()) is the number of keys.

bool

bool(td), if td:, and while td: raise a RuntimeError, so that assert td1 == td2 cannot pass by accident. To test for keys, use len(td.keys()). is_empty() tests for leaves: a tensordict that holds only empty sub-tensordicts is empty. To reduce a comparison, use (td1 == td2).all() or .any().

in

key in td tests the keys, as for a dict. A tuple of strings tests a nested key.

==

td == other compares each entry and returns a TensorDict of booleans, like a tensor. If the two tensordicts do not have the same keys, it raises a KeyError. Call .all() on the result to get a Python bool. td in some_list uses ==, so it raises unless td itself is in the list. A TensorDict is not hashable.

For example:

>>> td = TensorDict({"a": torch.arange(3), "nested": {"b": torch.zeros(3, 2)}}, batch_size=[3])
>>> [x.batch_size for x in td]
[torch.Size([]), torch.Size([]), torch.Size([])]
>>> len(td), len(td.keys())
(3, 2)
>>> bool(td)
Traceback (most recent call last):
...
RuntimeError: Converting a tensordict to boolean value is not permitted. Use len(td.keys()) ...
>>> td.is_empty()
False
>>> "a" in td, ("nested", "b") in td, "b" in td
(True, True, False)
>>> (td == td.clone()).all()
True

If a dataset returns tensordicts with no batch dimensions, the default collate function of torch.utils.data.DataLoader iterates over them and raises the same TypeError. Load data and share it between processes gives the collate_fn to use.
